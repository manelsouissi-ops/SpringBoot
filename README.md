# Product Catalogue - Spring Boot, Angular, Spring AI and MCP

This university project is a small product-catalogue application for the Polytechnique Sousse shop. It combines a Spring Boot REST API, an Angular chat-style interface, a PostgreSQL catalogue, Mistral through Spring AI, and a separate Model Context Protocol (MCP) server.

Its objectives are to manage products and categories through a REST API, display catalogue information in a web interface, and explore AI-assisted catalogue questions using tools. The backend prompts the assistant to answer in French and restrict catalogue-related responses.

> **Status at a glance:** the REST controllers, product/category persistence model, Angular interface, and MCP server module are present. The end-to-end AI/MCP integration is **not complete in the current source tree**; see [Known limitations](#known-limitations-and-security) before treating the chatbot or MCP tools as ready for demonstration.

## Architecture

```text
Angular UI (localhost:4200)
        |  development proxy: /agent, /chat, /produit
        v
Spring Boot REST API + Spring AI (localhost:8080)
        |                         |
        v                         v
PostgreSQL (springboot_db)   Mistral API / MCP client
                                      |
                                      v
                         MCP Server (localhost:9090/mcp)
                                      |
                                      v
                              PostgreSQL (springboot_db)
```

| Component | Location | Responsibility |
| --- | --- | --- |
| Spring Boot backend | repository root | REST endpoints for products and categories; Spring AI chat endpoint; JPA entities and repositories. |
| Angular frontend | `catalogue-frontend/` | Standalone Angular 21 UI that lists products and sends chat questions to the backend through the development proxy. |
| MCP Server | `MCP-Server/` | Separate Spring Boot/Spring AI WebMVC process configured for Streamable HTTP on port 9090. |

### Technologies

- Java 17, Spring Boot 4.1.x, Spring WebMVC, Spring Data JPA, Lombok, Maven Wrapper
- PostgreSQL JDBC driver and Hibernate/JPA
- Spring AI 2.0.1 with the Mistral starter and MCP client/server starters
- Angular 21.1, TypeScript 5.9, RxJS, Angular CLI, npm
- Springdoc OpenAPI UI (Swagger UI)

## Prerequisites (Windows)

Install the following before running the project:

- **JDK 17** and set `JAVA_HOME`.
- **Node.js and npm**. The checked project uses npm 11.8.0 and Angular 21.1.
- **PostgreSQL**, with a local server listening on `localhost:5432`.
- **Git**.
- A **Mistral API key** only if testing the AI chat endpoint.

The project provides Maven Wrapper scripts: `mvnw.cmd` at the root and in `MCP-Server`. A normal Windows command uses these scripts; installing Maven separately is a useful fallback if a wrapper cannot download or start Maven.

In PowerShell environments that block `npm.ps1`, invoke `npm.cmd` (and `npx.cmd`) instead of `npm`.

## PostgreSQL setup

The applications are configured to use a database named `springboot_db`, the PostgreSQL user `postgres`, and port `5432`.

Create the database with pgAdmin, or from `psql`:

```powershell
psql -U postgres -d postgres -c "CREATE DATABASE springboot_db;"
psql -U postgres -d springboot_db
```

The root backend uses `spring.jpa.hibernate.ddl-auto=validate`. It validates an existing schema; it does **not** create the tables. For a new local database, run the following SQL in `psql` before starting the root backend:

```sql
CREATE TABLE categorie (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nom VARCHAR(255) UNIQUE
);

CREATE TABLE produit (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nom VARCHAR(255),
    prix DOUBLE PRECISION NOT NULL,
    qte INTEGER NOT NULL,
    categorie_id BIGINT REFERENCES categorie(id)
);
```

The MCP module is set to `ddl-auto=update`, but its entities and repositories currently sit outside its application package scan; do not rely on it to create the schema. Use the SQL above for a predictable local setup.

## Environment variables and configuration

The root backend configuration is in `src/main/resources/application.properties`; the safe template is `src/main/resources/application.example.properties`.

Set variables for the current PowerShell session without putting secrets in source control:

```powershell
$env:DB_PASSWORD = '<your PostgreSQL password>'
$env:SPRING_AI_MISTRALAI_API_KEY = '<your Mistral API key>'
```

The backend reads `DB_PASSWORD` for PostgreSQL. `SPRING_AI_MISTRALAI_API_KEY` is Spring Boot's environment-variable form of `spring.ai.mistralai.api-key` and overrides that property without editing a file. The example configuration documents the intended `MISTRAL_API_KEY` placeholder, but the active configuration does not currently reference that placeholder. Never commit a real database password, API key, token, or a populated local configuration file.

Configuration values currently used by the modules are:

| Module | Database URL | Port | Other relevant setting |
| --- | --- | --- | --- |
| Root backend | `jdbc:postgresql://localhost:5432/springboot_db` | `8080` (Spring Boot default; no active port override) | JPA validation; Mistral model configured in properties. |
| MCP Server | `jdbc:postgresql://127.0.0.1:5432/springboot_db` | `9090` | `spring.ai.mcp.server.protocol=streamable`. |
| Angular dev server | n/a | `4200` (Angular CLI default) | `proxy.conf.json` forwards selected paths to port 8080. |

## Run the Spring Boot backend (port 8080)

1. Start PostgreSQL and create the schema.
2. Set `DB_PASSWORD`; set `SPRING_AI_MISTRALAI_API_KEY` if running the AI endpoint.
3. From the repository root, run:

```powershell
.\mvnw.cmd spring-boot:run
```

The REST API is then expected at `http://localhost:8080`.

If the wrapper prints `Cannot start maven from wrapper`, install Apache Maven, confirm `mvn -v` works in a new terminal, and run:

```powershell
mvn spring-boot:run
```

This fallback documents the wrapper failure observed in the inspected workspace; it does not change the project files.

## Run the Angular frontend (port 4200)

Open a second terminal:

```powershell
Set-Location catalogue-frontend
npm.cmd install
npm.cmd start
```

Open `http://localhost:4200/`.

`npm.cmd start` runs `ng serve`. Its proxy forwards `/agent`, `/chat`, and `/produit` to `http://127.0.0.1:8080`; therefore the root backend must be running for those UI actions. The frontend does not currently proxy `/categorie`.

### Current frontend features

- **Ask a question:** the chat form sends the typed question to `GET /agent` and keeps one generated conversation ID in browser `sessionStorage` for the current tab session.
- **View products:** the **Voir les produits** button calls `GET /produit/all` and displays the returned name, price, quantity, and category in the chat area.
- **Quick prompts:** **Statistiques** and **Rechercher** send fixed French questions to the chat endpoint. They do not call dedicated statistics or search REST endpoints.
- **Product creation form:** no product creation form exists in the current Angular source. Creating or updating a product is currently available only through the REST API/Swagger, not through the web interface.

## Run the MCP Server (port 9090)

Open a third terminal, keep PostgreSQL running, and set `DB_PASSWORD` in that terminal:

```powershell
Set-Location MCP-Server
.\mvnw.cmd spring-boot:run
```

Its configured Streamable HTTP endpoint is `http://localhost:9090/mcp`. This path is the default for Spring AI's Streamable HTTP WebMVC server and has not been overridden in the module configuration.

If the wrapper fails as described above, use `mvn spring-boot:run` after installing Maven.

## REST API

These are the HTTP routes implemented by the root backend controllers. There is no controller-level `/api` prefix.

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/produit/all` | List all products. |
| `GET` | `/produit/{id}` | Get one product; the current service returns `null` when it does not exist. |
| `GET` | `/produit/search?kw={keyword}` | Search products whose name contains `keyword`. |
| `POST` | `/produit/add` | Persist a product supplied as JSON. |
| `PUT` | `/produit/update/{id}` | Update an existing product from JSON; a missing ID produces no explicit response body. |
| `DELETE` | `/produit/{id}` | Delete a product by ID. |
| `GET` | `/categorie/all` | List all categories. |
| `GET` | `/agent?message={text}&conversationId={optional-id}` | Ask the Spring AI chat assistant. `conversationId` must match `[A-Za-z0-9._-]{1,128}` when provided. |
| `POST` | `/chat/confirm?reference={reference}` | Legacy local confirmation endpoint for a previously prepared product reference. No REST endpoint prepares that reference. |

Example body for product creation or update (the `categorie` object must refer to an existing category):

```json
{
  "nom": "Keyboard",
  "prix": 89.9,
  "quantite": 5,
  "categorie": { "id": 1 }
}
```

## Test the MCP Server with MCP Inspector

1. Start the MCP server on port 9090.
2. In a separate terminal, launch the Inspector against the Streamable HTTP endpoint:

```powershell
npx.cmd @modelcontextprotocol/inspector --transport http --server-url http://localhost:9090/mcp
```

3. Open the local Inspector URL printed by the command, connect, and inspect the **Tools** list. Test only read-only tools first with data that exists in PostgreSQL.

At present, an empty tools list is an expected result of the package-scanning limitation below. The server transport and `/mcp` route can be inspected, but successful tool discovery is not yet confirmed by the current code.

## Known limitations and security

- The root chat controller requires a `SyncMcpToolCallbackProvider`, but the root application properties do not define a `spring.ai.mcp.client` connection to the separate server. As a result, the backend-to-MCP connection is not configured in the committed project.
- In `MCP-Server`, the application class is under `com.example.mcpserver`, while the tool, entity, and repository classes are in top-level `tools`, `entites`, and `repository` packages. Spring Boot's default component/entity/repository scan will not discover those packages. Consequently, the MCP tool implementation is unfinished as wired.
- Only methods annotated with `@McpTool` are candidates for MCP discovery. In the current MCP tool class, `getProduct`, `prepareProduct`, and `getStatistiques` use that annotation; `getProducts` uses `@Tool` instead.
- The Angular UI currently uses only `GET /produit/all` and `GET /agent`. It has no category view, product create/update/delete form, or direct product-search UI.
- The root application properties currently contain a Mistral credential in the working tree. It is not repeated in this README. Treat it as exposed: revoke/rotate it in the provider console, remove it from tracked configuration, and supply a replacement through `SPRING_AI_MISTRALAI_API_KEY` (or change the property to reference a secret environment variable in a future code change). Do not commit a replacement credential.
- These limitations are documentation of the current source code, not changes made by this README task.

## Troubleshooting

| Symptom | Likely cause and check |
| --- | --- |
| `Cannot start maven from wrapper` | The Maven Wrapper did not start Maven in the terminal. Use the Maven fallback in the run sections after installing Maven; verify with `mvn -v`. |
| `npm` is blocked by PowerShell execution policy | Use `npm.cmd install` and `npm.cmd start`, as shown above. |
| Database authentication or connection failure | Ensure PostgreSQL is running on port 5432, database `springboot_db` exists, and `DB_PASSWORD` is set in the same terminal that starts the Java process. |
| Hibernate reports a missing table or schema validation fails | Run the SQL in [PostgreSQL setup](#postgresql-setup). The root backend uses `ddl-auto=validate` and will not create tables. |
| Angular says the backend is inaccessible | Start the root backend on port 8080, then restart `npm.cmd start` if needed. Check that the request path is one covered by `proxy.conf.json`. |
| Chat returns 429 or an AI service error | Check the Mistral account/quota and the environment-based API-key configuration. Do not paste credentials into issues, commits, or chat. |
| `/agent` fails at startup or cannot call tools | Review the missing root MCP client connection and MCP package-scan issues in [Known limitations and security](#known-limitations-and-security). |
| MCP Inspector connects but lists no tools | This is consistent with the current MCP module's package scan and mixed `@McpTool`/`@Tool` annotations. |

## Git collaboration for two students

Use a small, reviewable workflow so each student has a clear change set:

1. Agree on ownership, for example: Student A works on backend/MCP and Student B works on Angular/documentation. Avoid editing the same files at the same time.
2. Start work from an updated branch:

   ```powershell
   git switch main
   git pull origin main
   git switch -c feature/<short-description>
   ```

3. Make focused changes, test the affected module, and review the diff before committing:

   ```powershell
   git status
   git diff
   git add <files-you-intend-to-commit>
   git commit -m "feat: short description"
   git push -u origin feature/<short-description>
   ```

4. Open a pull request for the other student to review. Merge only after resolving comments and checking that secrets, build artefacts, and local configuration are not included.
5. Before beginning the next task, update the feature branch with the latest `main` and resolve any conflicts deliberately:

   ```powershell
   git fetch origin
   git merge origin/main
   ```

Never use force-push on a shared branch, never commit `.env` files or credentials, and coordinate before changing shared configuration, database schema, or dependencies.
